# itirpc

Модификация десктопного клиента **Яндекс.Музыка** для Windows: Discord Rich Presence,
скробблинг Last.fm, мини-плеер, глобальные хоткеи и диагностика клиента.

Мод **не даёт пользоваться сервисом без подписки Яндекс Плюс** и не пытается этого делать:
он ничего не меняет в авторизации, проверке подписки и запросах к API Яндекс.Музыки.
Все функции работают поверх обычного, оплаченного аккаунта.

### Скачивание треков — нереализуемо без обхода защиты

Функция **намеренно отключена**: `downloads.enabled: false`.

Загрузчик написан и работает: берёт подписанную ссылку на поток, которую клиент использует
сам, качает её с cookie аккаунта, показывает прогресс, не перезаписывает существующие файлы,
умеет вызывать ffmpeg. На живом треке скачалось 4,15 МБ.

Но **сохранённый файл нечитаемый**. Проверка содержимого: в первых 2 МБ нет ни `ftyp`, ни
`moov`, ни `mdat`, ни `ID3`, данные высокоэнтропийные. В пути потока есть сегмент
`/music-v2/crypt/` — клиент получает зашифрованные данные и расшифровывает их у себя.

Чтобы файл стал играбельным, нужно воспроизвести механизм защиты контента Яндекс.Музыки.
Это выходит за рамки мода и противоречит условию проекта — не давать пользоваться сервисом
в обход подписки. Поэтому функция выключена, а не оставлена «как будто работает».
Код загрузчика сохранён: он корректен и пригодится для любого незашифрованного источника.

### Чего мод не делает — и почему

Два подхода были опробованы и **убраны**, потому что ломали клиент или выходили за рамки:

1. **Перехват сетевых запросов.** `webRequest.onBeforeRequest` применялся, чтобы поймать адрес
   аудиопотока. Маска для шардированных хостов (`*.mds.yandex.net`) захватывала и
   `avatars.mds.yandex.net`, откуда берутся обложки и элементы оформления. В результате
   пропали аватарки, сломался дизайн и перестала играть музыка. Перехват удалён полностью;
   адрес потока берётся из медиаэлемента и из буфера ресурсов рендерера. Тест
   `the mod never intercepts network requests` не даёт вернуть его обратно.
2. **Подмена глобальных конструкторов рендерера.** Зонд подменял `window.Audio` и
   `document.createElement`, чтобы видеть медиаэлементы, не привязанные к DOM. Это заменяло
   глобальные объекты, от которых зависит весь рендерер. Вместо них — один узкий хук на
   `HTMLMediaElement.prototype.play`: он только запоминает элемент, через который идёт
   воспроизведение, и всегда вызывает оригинал с его же аргументами. Тест
   `the probe observes playback through one prototype method` фиксирует, что хук остался узким.

### Ещё не реализовано

- **Настраиваемая папка кеша.** Секция `cache.directory` есть в настройках, но **нигде не
  читается** — это заглушка, а не работающая функция. Реализация требует понимания того, как
  клиент хранит офлайн-репозиторий.
- **Управление плеером с других устройств** (телефон и т. п.) — требует работы с протоколом
  Ynison, это отдельный крупный модуль.
- **Last.fm** — код написан и покрыт тестами, но **живьём не проверен**: нужны ваш API key
  и авторизация.
- **UI-панель настроек внутри приложения** — сейчас настройки живут в JSON и в трее.
- **Улучшенная анимация «Моей Волны» с настройкой FPS** и **поиск при добавлении трека
  в плейлист** — требуют правки рендерера.
- **Исправления багов ванильного клиента** (чёткость при нечётных размерах, медиаконтекст
  при кроссфейде, застревание AAC на 1:00, адаптация кнопок плеера) — точки внедрения найдены,
  правки не внесены.
- **Эксперименты Яндекс.Музыки и разблокировка DevTools** — требуют правки минифицированных
  чанков рендерера, что сознательно не делается (см. ниже).
- **Трансляция на Яндекс.Станции, каталог плагинов, OBS-виджет, профиль, Windows Media Control.**

## Как это устроено

Ключевое архитектурное решение: **мод живёт целиком в main-процессе клиента и правит ровно
одну строку в `app.asar`.**

```
'use strict';require('./itirpc/bootstrap.js');const electron=require('electron')...
```

### Почему не правятся чанки рендерера

Известные моды (например, `YandexMusicModClient`) собирают **собственный `app.asar` целиком** —
свою копию всех 2157 файлов клиента, включая минифицированные чанки `app/_next/static/chunks/*.js`.
Из-за этого при каждом обновлении Яндекс.Музыки автор вынужден вручную переносить изменённые
чанки, а регулярные выражения привязаны к именам переменных минификатора (`c.qV`, `c.yc`).

itirpc так не делает. Вместо этого используется то, что клиент **уже сам** публикует всё нужное:

- `navigator.mediaSession.metadata` — рендерер выставляет `MediaMetadata` с названием,
  исполнителем, альбомом и обложками для системных медиаклавиш;
- `navigator.mediaSession.setPositionState()` — публикует длительность и позицию.

Мод читает эти данные из main-процесса через `webContents.executeJavaScript`, обернув
`setPositionState`, чтобы запоминать позицию (у MediaSession нет геттера). Живой прогресс берётся
из самого медиаэлемента, который перехватывается обёрткой над `window.Audio` и
`document.createElement`.

Итог: **ни один минифицированный файл клиента не изменяется**, и патч переживает почти любое
обновление Яндекс.Музыки.

### Точки интеграции

| Что | Как |
| --- | --- |
| Запуск мода | `require('./itirpc/bootstrap.js')` в начале `index.js` |
| Окно клиента | `app.on('browser-window-created')` + проверка URL `music-application://desktop` |
| Управление плеером | штатный IPC-канал клиента `desktop:player:action` |
| Громкость и перемотка | обёртки над медиаэлементом через `executeJavaScript` |
| Метаданные и прогресс | `navigator.mediaSession` через `executeJavaScript` |
| Масштаб | `webContents.setZoomFactor`, повторно после каждой навигации |
| Кодек и битрейт | разбор URL медиаэлемента; резерв — буфер ресурсов рендерера |

### Как определяется кодек

Адрес потока берётся из самого медиаэлемента: клиент играет обычный прогрессивный файл,
поэтому `media.currentSrc` содержит настоящий URL вида

```
https://strm-mar-238.strm.yandex.net/music-v2/crypt/ysign1=…/aac192-mp4?container=mp4&codec=mp4a.40.2
```

`aac192` — это кодек и битрейт. Разбор намеренно строгий: принимаются только явные маркеры
(`aac192`, `mp3_320`, `codec=mp4a`, `bitrate=`, `192kbps`), потому что первая версия искала
любое двузначное число и выдавала номер шарда из имени хоста `strm-mar-135` за битрейт 135 —
при настоящих 192. Оба случая закреплены тестами на реальном URL.

Резервный источник — `performance.getEntriesByType('resource')` в рендерере.
Сетевой перехват для этого не нужен и не используется (см. ниже).

### Проверка целостности asar — обязательный шаг

Клиент собран с включённой проверкой `EnableEmbeddedAsarIntegrityValidation`: SHA256
заголовка `app.asar` зашит ASCII-строкой прямо в `Яндекс Музыка.exe` (ровно одно вхождение).
Любая перепаковка архива меняет заголовок, поэтому toolset **обязан** перезаписать этот хеш,
иначе клиент не запустится.

Длина строки (64 hex-символа) не меняется, поэтому правка выполняется на месте, без изменения
размера exe. Резервные копии создаются и для `app.asar`, и для exe.

### Формат asar

Упаковщик написан с нуля, без `@electron/asar` (в проекте нет сети и `node_modules`).
Он воспроизводит формат побайтово, включая:

- pickle-заголовки `[uint32 payloadSize][uint32 jsonLength][json][padding]`;
- поле `integrity` с `algorithm`, `hash`, `blockSize: 4194304` и массивом `blocks`;
- флаг `executable` и порядок записей, унаследованный от оригинала.

Корректность доказана тестом round-trip: распаковка релизного `app.asar` (2157 файлов,
50,8 МиБ) и обратная упаковка дают **побайтово идентичный файл**.

## Установка

Требования: Windows, установленный клиент Яндекс.Музыки, Node.js 18+.

```powershell
node toolset.js info      # проверить, что клиент найден и версия определена
node toolset.js install --kill --launch
```

`--kill` закроет запущенный клиент, `--launch` запустит его после установки.
Без этих флагов клиент нужно закрыть вручную — toolset откажется работать с запущенным
приложением, чтобы не повредить архив.

Другие команды:

```powershell
node toolset.js doctor     # диагностика: патч, бэкапы, согласованность хеша exe
node toolset.js config     # показать все настройки
node toolset.js restore    # вернуть исходный клиент (asar + exe)
node toolset.js rebuild --kill --launch   # быстрая пересборка после правок в src/
node toolset.js help
```

## Настройка Discord Rich Presence

1. Откройте <https://discord.com/developers/applications> → **New Application**.
2. Скопируйте **Application ID** (это не секрет, его можно публиковать).
3. Впишите его в настройки:

```powershell
node toolset.js config discord.clientId 1234567890123456789
```

Мод подхватит изменение **без перезапуска** — достаточно начать новый трек.

> **Почему clientId не встроен в мод.** Готовый clientId означал бы, что все пользователи
> публикуют активность под чужим приложением Discord. Свой ID каждый создаёт сам — это
> бесплатно и занимает минуту.

### Как выглядит статус

```
Играет:   [обложка]  Холод
                   Сплин — Пример семьи
                   ▓▓▓▓▓▓░░░░░░░  1:23 / 3:07

Пауза:   [обложка]  Холод
                   ⏸ На паузе
```

Пауза передаётся **сразу**, как только плеер её сообщил: вторая строка меняется
на «На паузе», прогресс-бар исчезает, но обложка и название трека остаются.
Ничего не дублируется — клиент часто присылает в `album` то же название трека,
поэтому строки под обложкой нет.

### Иконки статуса

Мод использует **внешние обложки** — прямые URL CDN Яндекса, которые Discord проксирует сам.
Загружать что-либо в приложение не нужно.

Маленькая иконка (`small_image`) требует ключа, загруженного в ваше приложение Discord.
Если он есть, укажите его:

```powershell
node toolset.js config discord.smallImageKey playing
```

Без него статус всё равно работает: «На паузе» пишется словом во второй строке,
а прогресс-бар при этом исчезает.

### Про «пропадание активности через минуту»

Это давняя жалоба на Discord RPC. Мод решает её тремя механизмами:

- **heartbeat** — активность переотправляется каждые 30 секунд, даже если не изменилась;
- **реконнект** — при разрыве сокета подключение восстанавливается с заданным интервалом;
- **PING/PONG** — транспорт сам отвечает на служебные кадры Discord.

## Настройка Last.fm

Мод не содержит чужих API-ключей. Зарегистрируйте собственное приложение:

1. <https://www.last.fm/api/account/create> → заполните название и описание.
2. Скопируйте **API key** и **Shared secret**:

```powershell
node toolset.js config lastfm.apiKey        <API_KEY>
node toolset.js config lastfm.sharedSecret  <SHARED_SECRET>
```

3. Авторизуйтесь: правый клик по значку **itirpc** в трее → **Авторизоваться в Last.fm**.
   Откроется окно Last.fm; после подтверждения доступа оно закроется само, а мод сохранит сессию.

### Правило засчитывания

Повторяет [правило Last.fm](https://www.last.fm/api/scrobbling#when-is-a-scrobble-a-scrobble):

- трек короче **30 секунд** не скробблится вообще;
- иначе нужно прослушать **не менее половины трека**, но не больше **4 минут**;
- запрос отправляется **при смене трека** и при паузе;
- время считается по настенным часам, поэтому перемотка вперёд не создаёт «прослушанное» время.

Порог можно изменить: `node toolset.js config lastfm.scrobbleThresholdPercent 50`
(изменение порога в текущей реализации влияет на подпись в логах; базовое правило — стандарт Last.fm).

для мини-плеера используется `Ctrl+Alt+M`.

## Мини-плеер

Открывается по хоткею, из трея или автоматически (`miniplayer.openOnStart`).

- адаптивная вёрстка: при ширине меньше 268 px обложка и вторая строка скрываются,
  при высоте меньше 108 px убирается строка времени;
- бейдж с кодеком и битрейтом текущего потока (отключается через `ui.showCodec`);
- клик по полосе прогресса — перемотка;
- кнопка-«булавка» закрепляет окно поверх остальных, состояние сохраняется;
- позиция и размер окна запоминаются;
- `Esc` или крестик скрывают окно (не закрывают), `Пробел` — пауза.

Окно изолировано: собственный `preload.js` с `contextIsolation`, `sandbox: true`,
строгим CSP и IPC-каналами в пространстве имён `itirpc:mini:*`. Команды принимаются
только от собственного окна мода.

## Обновление клиента Яндекс.Музыки

Автообновление — главный риск для любого мода. Возможны два сценария:

1. **Обновился только `app.asar`** (клиент заменил архив, оставив пропатченный exe).
   Тогда хеш в exe перестанет соответствовать архиву, и клиент **не запустится**.
2. **Обновился весь клиент** (обычный NSIS-инсталлятор). Патч пропадёт, клиент заработает
   как ванильный.

Для диагностики и восстановления:

```powershell
node toolset.js doctor      # покажет рассогласование хеша
node toolset.js restore     # вернёт исходный asar и exe
node toolset.js install --kill --launch   # поставит мод на новую версию
```

`doctor` проверяет:

1. есть ли патч в `app.asar`;
2. целы ли резервные копии;
3. согласован ли хеш целостности в exe с текущим архивом;
4. не изменился ли якорь патча (`'use strict';` в начале `index.js`).

Если пункт 4 не проходит, структура main-процесса изменилась и патч нужно адаптировать —
toolset сообщит об этом явной ошибкой вместо порчи файла.

```powershell

```

Пересобирает `src/` → `dist/`, перепаковывает `app.asar`, правит хеш в exe, перезапускает клиент.

### Про язык

Спецификация предполагала TypeScript. В этом окружении нет доступа к npm-реестру, поэтому
`tsc` и `esbuild` недоступны, и мод написан на **plain JavaScript (CommonJS) с JSDoc-аннотациями**.
Код не использует синтаксис, несовместимый с TypeScript, и переход на TS сводится к добавлению
`tsconfig.json` и переименованию файлов.

## Ограничения

- **Только Windows.** Правка хеша в exe и пути рассчитаны на Windows-сборку. macOS потребует
  правки `Info.plist` (`ElectronAsarIntegrity`) и переподписи, Linux — своей логики.
- **Яндекс.Музыка должна быть установлена** в стандартный путь (`%LOCALAPPDATA%\Programs\YandexMusic`).
- **Проверено на версии 5.122.0.** На других версиях механика та же, но якорь патча и смещение
  хеша в exe могут отличаться — `doctor` это покажет.
- **Клиент нельзя запускать из копии папки.** Приложение отказывается работать вне места
  установки (падает на старте), поэтому тестировать патч можно только на реальной установке.
- **Запуск из окружений с переменной `ELECTRON_RUN_AS_NODE=1`** приводит к молчаливому выходу
  с кодом 0. `toolset.js run` сам удаляет эту переменную для дочернего процесса.
- **Подписка Яндекс Плюс обязательна.** Мод намеренно не вмешивается в авторизацию и проверку
  подписки и не предоставляет способа обойти её.
